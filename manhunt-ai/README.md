# Manhunt AI Survivors (experimental 0.2)

AI survivor overlay for X4yii/Automata, pinned to upstream commit 5bf94f646ff6cc0fb07b20c1067f9c393d451225. GPL-3.0 upstream license applies; the assembled source retains the upstream LICENSE. Upstream: https://github.com/X4yii/Automata

Target: Minecraft 1.12.2 / Cleanroom 0.7.14-alpha, JDK 25 build. Server-side AI EntityPlayerMP bodies, explicitly identified with AI_ prefix and not counted as authenticated humans. Optional reflective adapters for Cotesia and Modular Warfare. Includes patrol, pathfinding, basic melee/gun behavior, food, bounded 2x2 crafting, administrator-controlled building and basic Russian chat replies. Not a tested release; no automatic turret setup, autonomous progression or LLM integration yet.

Build locally: check out the pinned upstream commit, run python3 manhunt-ai/apply_overlay.py /path/to/Automata, then run bash gradlew build --no-daemon in that checkout. GitHub Actions, if enabled, assembles the same source and uploads the built JAR and complete source archive.

Do not install on a production server before testing. No private modpack jars, configs, credentials, or player chat logs are included.

## Tactical AI 0.3

- Local decision layer every AI drive tick; perception every 4 ticks while alerted / 10 idle, or 8 / 24 under load. These are scheduling intervals, not benchmarked response times.
- Damage events and nearby explosion events trigger immediate alert state. Nearby visible SRP explosives, clouds and incoming projectiles trigger evasion. No global map or chunk loading is intended.
- Short-term last-visible threat memory, escape destinations, stale route cancellation, stuck recovery and opportunistic pickup of unowned visible supplies.
- /manhuntai list includes measured mean AI time, mean server tick interval and degraded mode. Optional scans and crafting slow down under pressure; this is not a hard CPU cap.
- Standalone BrainSelfTest checks 11 action cases plus scan cadence. Full Forge/Cleanroom integration and mod-specific APIs remain unverified until successful CI and a dedicated test server run.
- No full crafting progression, automated turret configuration, persistent memory or LLM dialogue yet. AI identity remains explicit.

## Autonomous survival 0.4 (experimental)

New modules: SurvivorProgression (six stable role labels and deterministic needs policy), SurvivorWork (local gathering and workbench tasks), SurvivorTechnology (bounded backward recipe planner), SurvivorMemory (WorldSavedData per dimension), SurvivorPermissions (vanilla and Clans permission checks).

- Enable a bot's autonomous work explicitly with /manhuntai auto <name> on. Disable with off. Operator permission level 2 required. Local work radius is 12 blocks from its initial home; no forced chunk loading; only visible vanilla logs and stone/cobblestone are autonomous mining targets. No raids or arbitrary block excavation.
- Actual break progress, tool selection, vanilla harvesting and pickup. Workers reserve targets to avoid duplicating work. Inventory-based progression through planks, sticks, crafting table, wooden and stone tools and a basic 5x5 perimeter. A queued perimeter is not guaranteed completed. Six role labels; only builder priority is currently distinct in progression policy.
- 3x3 crafting requires a nearby visible, permitted workbench. Technology goal: /manhuntai goal <name> <registry-item-id>, or clear. Goals use item IDs (not metadata/NBT subtypes), real registry recipes and a bounded recursive search. Allowed namespaces: minecraft, thermalfoundation, thermalexpansion, thermaldynamics, openmodularturrets, modularwarfare. Goals do not support machine recipes, smelting, multiblocks, custom workbenches or actual turret ownership/power setup. /manhuntai list displays current goal and a candidate missing ingredient, not a complete bill of materials.
- Persistence: last resource/bench/threat locations and bounded counters. Not a full persistent player inventory, personality or offline agent simulation. No chat transcripts retained.
- Optional adapter calls the actual Modular Warfare basic server reload handler; enhanced weapons needing animation-task completion intentionally skipped. The adapter signatures were inspected in the supplied jar. Cotesia API signatures were recovered from intact entries of the truncated supplied jar; full jar remains unusable for testing. Clans block-break and placement API signatures also inspected. All three adapters still need live integration tests.
- Vanilla armor/shield selection, explicit AI squad warning messages, rate-limited Russian status replies. No external LLM yet. AI identity remains explicit and not included in authenticated player count.
- Standalone progression tests: 14 cases passed locally on JDK 21, and are included in the JDK 25 CI workflow. Full Gradle build and server behavior not verified. Do not deploy on production until CI and integration tests pass.

## Version 0.5 — Persistence and industrial work (experimental)

- `/manhuntai park <name>`, `/manhuntai parked`, `/manhuntai resume <name>`: dimension-local saved inventory, health, food, home, last position and progression settings. Normal orderly shutdown parks living AI. Explicit resume requires its saved position to be loaded and standable. This is not crash-atomic persistence; in-flight furnace jobs and temporary effects are not restored.
- `/manhuntai furnace <name>`: queues placement of a carried vanilla furnace. `/manhuntai smelt <name> <input-item-id>`: a single real furnace operation, with a carried input and coal. Only a station placed by this agent in its current session is eligible. Existing contents are not taken. On interruption, remaining materials stay in the furnace. Vanilla smelting time is unchanged. These operations do not support Thermal machines, RF, or turret configuration yet.
- `/manhuntai industry <name> on` plus `/manhuntai auto <name> on`: experimental iron-tool progression using visible coal/iron ore, real harvesting and the agent's furnace. Limited to the local home radius. No underground omniscience, claim bypass, forced chunks or guaranteed resource availability.
- Actual Clans container-interaction API signature verified with javap on the supplied 2.1.9 JAR. Runtime permission and machine behavior still require integration testing.
- Optional local dialogue: install and run Ollama separately, set the server process environment variable `MANHUNT_AI_OLLAMA_MODEL` to an installed model name. Only directly addressed messages (`@AI_name ...`) are sent to loopback 127.0.0.1:11434. Tell players about this processing before enabling. Single worker, bounded queue, request timeout, fallback replies; no model-generated game commands, no external API, no fake human identity. Model output can still be inaccurate and is not used for gameplay decisions. Disabled unless the variable is set.
- CI now supports a draft PR for build visibility and cancels superseded runs on the same ref. The full Gradle build has not been verified; no production-ready binary is claimed.

## Version 0.6 — Collective construction (experimental)

- `/manhuntai squadbuild <leader>` distributes a 5x5 two-level perimeter among up to six nearby AI agents with nearby home positions. The entrance is left open. Each worker handles both levels of its assigned columns; 30 blocks total. Requires real supplies and permissions. This is a wall plan, not a roofed complete base. Placement success depends on terrain, visibility, pathfinding and materials.
- Construction uses a standable adjacent approach instead of navigating to the target block itself; it rejects self-intersecting placement and reports placed/skipped/queued counts in activity status.
- Furnace jobs reuse residual heat and their own previously inserted coal. Stalled jobs expire without deleting materials in the world.
- Standalone blueprint tests: all 12 partition scenarios passed locally. CI includes this test suite.
- CI fixes: full upstream git history and tags for Cleanroom versioning; use non-generic Forge 1.12.2 IShapedRecipe. Run 54 reached Java compilation and reported two instances of that interface error. Fixed in source; full build pending confirmation.

## Version 0.7 — Squad logistics and personalities (experimental)

- Version 0.6 compiled successfully in GitHub Actions run 46045980802. Runtime mod archive is automata-1.2.0-local.dirty.jar; it replaces upstream Automata, not an additional mod. This is a successful compilation, not an in-game compatibility test.
- Six deterministic dialogue styles (practical, cautious, friendly, reserved, optimistic, analytical). The stable AI identity is always visible; the style and actual state are passed to the optional local language model.
- Nearby autonomous agents with neighboring homes can share surplus vanilla prepared food, planks, cobblestone, coal and iron. Maximum eight items per transfer, at most one transfer every 100 ticks for the squad; transfer requires proximity and sight and is suppressed during threats or server stress. Role-specific reserves and deficits keep supplies from being exhausted. No human inventory access. The exchange generates two short AI-labelled lines based on the actual transfer, not a fabricated event.

- Real turret ownership/configuration, Thermal machine/RF networks, clan membership, full autonomous logistics navigation and free-form inter-agent LLM conversations remain unimplemented. The exact pack archive is too large for the connected download limit; do not guess mod-specific APIs.

## Version 0.8 — Population and adaptive defense (experimental)

- Default configuration `config/manhunt-ai.cfg`: population.enabled=true, population.target=4 (range 0..6). Director polls every second, starts recruitment after 200 server ticks, and schedules one successful join per 240 ticks. Overworld only, loaded chunks only. It waits if no safe usable site exists or the server is stressed. It prioritizes saved snapshots for its six reserved AI names when their positions are loaded and free. Nearby independent camps use separate home positions. No remote login or spoofed authenticated player count. Every actual AI join/leave announces its AI identity in public chat.
- Fresh automatic agents start with autonomous work and industry enabled. First recruitment provides the existing iron sword and eight bread; the per-world recruited marker prevents giving a fresh kit on every death. Death replacement waits 5–20 minutes depending on repeated deaths in the current session. Clean shutdown stores snapshots; no crash-atomic guarantee. Admin `/manhuntai population off` stops recruitment without killing active agents, `population on` resumes it, and `population 0..6` changes the desired recruitment ceiling. `/manhuntai clear` disables recruitment and removes active agents. Manual park/remove suppresses that name until restart or explicit population enable.
- Local threat assessment counts visible nearby hostile entities and compares target health. Critical injury, numerical disadvantage, explosive/projectile hazards, and very strong targets can trigger retreat. Safe eating at a distance, better sword/food choice, local escape movement while pathfinding, and actual hostile kill reports. No automatic damage or invulnerability.
- Autonomous agents periodically inspect their 5x5 two-level wall perimeter and queue missing blocks using only permitted solid building materials in inventory, keeping a small reserve. The worker tries to acquire additional visible stone to fill deficits. Existing structures are not demolished. Wall repair is not a guaranteed complete roofed or parasite-proof base.
- Low-food recovery: real crafting of bread, use of the agent's own furnace for carried raw ingredients, or conservative hunting of unnamed, non-leashed adult vanilla livestock in the agent's immediate territory, away from humans and visible fences; actual melee damage and drops. Hostile defense interrupts hunting. No food spawning.
- CI adds 1872 population scheduling combinations, 100 retry/death delay checks and eight defense assertions. New integration requires a successful build and a test server; auto-spawn is experimental. Disable recruitment before production deployment until tested. Thermal RF machine use, actual turret configuration, full faction/clan integration, remote LLM and cross-chunk offline simulation are not implemented.

## Version 0.9 — Siege survival and mutual assistance (experimental)

- The first and subsequent successful automatic joins are scheduled randomly 1200–12000 server ticks (1–10 minutes at 20 TPS). Unsafe or unloaded terrain and high server load can postpone joins. No artificial authenticated player count. Default four agents, maximum six.
- Recruitment searches loaded overworld surfaces and sampled floors under roofs, preferring covered sites with usable ground. It rejects nearby hostile entities within a 24-block bounding box and nearby actual players. It may expand the search around loaded human areas after failed attempts; respects known protection checks, never forces chunks. No guarantee of a safe site in a fully infested world.
- `population.siegeStarterKit=true` in config/manhunt-ai.cfg: first automatic recruitment gets iron armor/tools/sword, shield, bow and 64 arrows, 24 bread, 64 cobblestone, 16 planks and 16 torches. This is a configurable balance choice; no repeated starter kit after death. Existing saved agents retain their own equipment. Bow uses normal Minecraft charging and ammunition; checks ally line of sight (not a guaranteed ballistic friendly-fire filter).
- Automatic repair/expansion uses a 55-block 5x5 shelter blueprint: two-layer walls and roof built from perimeter inward, open entrance. Uses actual inventory and protection checks. No guarantee of full completion or resistance to parasite block breaking. Very high-health foes are avoided in melee, and recovery and escape outrank combat.
- Help requests use structured local events, with four priorities: construction materials 25, food 55, combat 75, emergency 95. Nearby agents may accept, refuse due to higher/equal priority, danger or missing supplies. Accepted jobs navigate toward the requesting agent, target actual visible hostiles or transfer real surplus. Tasks expire and can be interrupted. Requests are rate-limited and chat is explicitly AI-labelled, visible to nearby humans. No fake chat events or remote access. Inter-agent messages are generated from actual decisions, not by parsing unrestricted text commands.
- CI tests added for 10000 join delays, 16 help decisions and shelter plan. 0.8 compiled successfully in run 46047143244; 0.9 build and actual gameplay need verification. Existing modpack turret and RF integrations are still missing; test on a copy of the server before enabling population.

## Version 0.10 — Combat readiness and Cotesia choice (experimental)

- Before activation, the AI invokes the same Cotesia server-side handler as the initial faction menu: AcceptChoicePacket(EnumChoice.HUMAN).handle(EntityPlayerMP). Checks hasMadeDecision and !isParasite; fails closed if selection cannot be confirmed. Recovered class signatures and bytecode from the supplied damaged JAR (central directory missing); no complete live Cotesia test performed. Never changes an authenticated player's choice.
- Automatic new recruits have ordinary profile names (Alex, Boris, Mira, etc.), but TAB explicitly shows [ИИ], and chat/join announcements remain AI-labelled. Existing snapshot names and keys remain usable. Authenticated users take precedence on name conflicts. No spoofed human population.
- Equipment work crafts shields, vanilla iron/leather armor, swords, bows and arrows, replaces damaged equal-tier gear and continues iron production for equipment. Discovers real registered Modular Warfare weapon, magazine and compatible bullet recipes using the supplied mod's GunType and BaseType fields. Does not fabricate ammunition or create missing machine/custom recipes. BASIC reload adapter remains experimental; ENHANCED reload still requires the genuine animation-task lifecycle and is not implemented. Empty magazines may require filling via the mod's separate reload mechanic.
- Combat: threat scanning every two ticks under normal combat load, immediate attack-event alerts, revalidate equipped gun, faster retry and actual weapon cooldown, strafing and backpedaling on safe footing, shield between attacks, retreat from oversized enemies instead of entering melee. No invulnerability or guaranteed success against evolved parasites.
- Assistance chat now uses varied colloquial Russian and profanity in actual AI-to-AI assistance situations. Refusals and accepted deliveries are grounded in real needs and actions; no insults directed at authenticated players. Local model remains optional.
- 0.9 successfully built in CI run 46047621055. 0.10 must still compile and pass a dedicated server test. No claim of runtime compatibility with the entire pack.

## Version 0.11 — Coordinated anti-parasite defense (experimental)

- Confirmed Cotesia parasite players are prioritized as in-game vagrant opponents; humans, spectators and creative players are not selected as enemies by this classifier. Observed enemy contacts are shared locally with nearby agents. Contact messages distinguish vagrants from hostile mobs and are limited per target (160 ticks, bounded cache). AI-labelled Russian battle cries reflect actual observations and tactical decisions, not unrestricted harassment or fake human messages.
- New pure combat policy chooses ENGAGE, COVER or WITHDRAW using health, armor, available ranged/melee equipment, nearby visible enemies and nearby allies' estimated strength. Conservative attack threshold 1.25; ranged covering threshold 0.60; severe injury or environmental danger forces withdrawal. Enemy health and armor are remembered from actual sightings; this is a heuristic, not an exact prediction of modded damage or abilities. Reassessment every 4 ticks normally, 12 under load; retreat hysteresis 40 ticks. Visible vagrants and shared targets receive greater targeting priority, but do not override self-preservation. Nearby support requires sight of the same enemy, sufficient health and weapons.
- Retreat candidates favor intervening blocks/roof and proximity to home; approach beyond 32 blocks from home is restricted. Existing pathfinding, shield, projectile evasion, weapon cooldown and assistance systems are retained. Diagnostic list includes current tactical order. No infinite ammunition, artificial damage or claim bypass.
- Manual new spawn names no longer have the AI_ prefix; automatic recruits already use ordinary names. Existing saves remain compatible. Explicit [ИИ] in TAB and AI chat/join disclosure retained; authenticated player counts unchanged.
- 10 new pure combat policy checks in CI. Version 0.10 compiled successfully in run 46048439420. Version 0.11 compilation and live server behavior remain unverified until new CI and gameplay tests finish. Enhanced weapon reload, turrets and RF integration remain incomplete.

## Version 0.12 — Stronghold and navigation (experimental)

- Live terrain checks reject lava/fire/cactus/magma/web, water, unsafe support, unloaded chunks and positions beyond the world border. A* uses higher hazard/edge and water costs, checks walk smoothing for edges, and enables ladder edges for Manhunt only (global cost changes also affect the original Automata pathfinder). Normal path budget 4096 nodes/18 ms worker search, reduced under stress. Failed route positions receive bounded, decaying costs. Movement turns before advancing and validates footing and landing. Paths remain bounded best-effort, not guaranteed globally shortest. No destructive tunneling or forced loading.
- Recruitment favors naturally elevated or rooftop sites with usable ground (18/25 local cells), two sampled walking exits, and no nearby detected hostile entities. This is a heuristic, not a promise of parasite-proof terrain. A 76-solid-block stronghold plan includes 30 wall blocks, 24 roof blocks (ladder shaft), 16 parapet blocks, and six entrance baffle blocks. Real ladder (up to four pieces), wooden gate and lighting tasks, armed roof patrol, repair and supply checks. Existing solid roofs are not forcibly demolished. Requires materials, safe supports, access and permissions. No magic floating base or guaranteed completion.
- Optional /manhuntai lava <name> <x> <y> <z> places a carried lava bucket using vanilla interaction only into an existing fully contained stone basin, outside the core, after checking permissions, surrounding flammables and nearby entities. It does not build an open flowing lava wall; a basin can become unsafe if parasites break it later.
- Optional /manhuntai defense <name> <x> <y> <z> <ammo-id> <side> authorizes a service task at a preconfigured Open Modular Turrets base within the agent's local radius, with the explicit sided input and ammo registry ID. It monitors Forge Energy capability and uses accepted item handler insertion with actual carried ammo (or attempts registered ammo recipes at a nearby workbench). /manhuntai defense <name> clear cancels it. The task is session-local and expires after 20 minutes. It does not change turret owner, targets, trusted users, or create energy. Install/configure the base and head and verify friendly targeting yourself; exact custom turret/RF and lift APIs are unavailable. No fully autonomous turret installation, RF generation network, powered lift or flowing lava defenses yet.
- CI adds stronghold geometry/support/shaft tests and exact upstream navigation patch anchors. 0.11 built successfully in run 46048921061. The 0.12 build and live gameplay remain to be verified. Test on a world copy first.

## Version 0.13 — Season progression and modpack integration (experimental)

Inspected actual supplied SRParasites-1.10.9.jar, SRPOverLast-1.0.1.jar, openmodularturrets-4.0.1-mc1.12.2-forge.jar and mcheli-ce-1.5.1-embedded-recipes.jar (ZIP entries and javap signatures/bytecode). No third-party jar uploaded to the repository.

- SRP: collect visible unowned loot including lure components, lures, hearts and rare vanilla ingredients; craft lureblock through lureblock6 from actual registry recipes (metadata 0..5). Keep them for final specimen. Nearby calm agents pool real materials into a more advanced teammate. OverLast final_specimen recipe requires all six lure variants, two nether stars and dragon egg. Purifier recipes use real biome/colony ingredients. After specimen, prepare nine mineral blocks and a beacon from actual recipes; beacon requires a further nether star. No spawning rare items, no automated Wither/End dragon campaign, and no guaranteed season completion. Metadata-aware dependency planning supports SRP, OverLast, OMT and MCHeli ordinary components; aircraft recipes require their real drafting table instead.
- OverLast: /manhuntai preparearena <name> <x> <y> <z> assigns a nearby open-sky beacon position; builds 3x3 mineral foundation where space is empty, places final specimen adjacent when possible, does not demolish existing blocks. /manhuntai arena <x> <y> <z> invokes actual structure validator. Valid structure needs beacon at origin, nine mineral blocks below, specimen within radius three, allowed arena blocks and clear sky across 11x11. The base and combat arena must be separate. Actual beacon placement starts the global event; operator must authorize this, no fake score or debug calls. Read actual wave, dimension, scoring and participant radii, structure state. Armed healthy local agents attempt to rendezvous with an active arena. OverLast obtains its active participants from authenticated PlayerList, while kills check actual EntityPlayer source and radius; AI are not included in real online count. Humans may be required to prevent absence penalties. No automatic cross-dimension travel or guaranteed event win.
- OMT: engineer/guard agents attempt actual tier-1 base (metadata 0) and disposable head recipes, using recursively resolved metadata-specific ingredients. Normal placement assigns owner through the real BlockTurretBase handler. Configure only newly agent-placed base for hostile mobs, not neutral or player targets. Supply its real ammo inventory via getInventory().getAmmoSlots(), and only use cobblestone if DisposableAmmo.getDamage accepts it. Can transfer existing stored Forge Energy from compatible single charged Thermal Expansion items, not generate RF; no power creation or autonomous generator/cable grid. Ownership and actual targeting need live testing, existing unrelated bases not claimed. The preconfigured defense command remains available.
- MCHeli: /manhuntai vehicle <name> <registered-recipe-id> queues crafting an aircraft/vehicle item through MCH_DraftingTableGuiContainer.createRecipeItem and ordinary output transfer. Agent crafts/places drafting table and walks to it. Uses real MCH_Recipes.canCraft, not free item creation or normal workbench bypass. Driving, pilot control, targeting, vehicle fuel/ammo loading and combat use are not implemented. Exact machine APIs for Thermal not supplied.
- Normal agent nicknames remain; transparent AI designation in TAB and chat retained. 0.12 built successfully in run 46049789793. 0.13 source must compile and be tested in game; no claim of full modpack completion.
